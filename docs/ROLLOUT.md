# Rolling TokenFin out to a team (20-developer playbook)

Goal: every developer's Claude Code (and Codex / Gemini / OpenCode where used) sends usage to your
TokenFin workspace, attributed to the right person and team, with privacy settings you chose on
purpose — in about an hour of admin time.

There are two ways to get a machine connected. Most teams use both:

| | **A. Managed settings (MDM)** | **B. Developer runs the CLI** |
|---|---|---|
| Who acts | IT / admin, once | Each developer, once per machine |
| Agents | Claude Code | Claude Code, Codex CLI, Gemini CLI, OpenCode |
| Key | One org **ingest-only** key in a system file | Per-device ingest + read keys |
| Attribution | `user.email` Claude Code puts on every event | The key's user, plus `user.email` |
| Developer can turn it off | No (managed settings win) | Yes (`npx tokenfin@latest remove`) |
| Extras | — | `budget`, statusline, MCP queries from chat |

---

## 0. Before you start (10 min)

1. **Workspace + members.** Create the workspace, then invite everyone (Teams → Invite, or the
   onboarding invite step). Members must accept so their email maps to a member — events from an
   email that isn't a member still count toward the org, but not toward a person.
2. **Teams.** Create teams (Teams page) if you want per-team budgets. For cost allocation from
   telemetry, you'll also tag machines with `team.name` (step 1).
3. **Decide on prompt text.** By default connected agents send **the text of each prompt** so you
   can see which prompts cost what. It's stored for 90 days and visible to workspace admins. If
   that's not acceptable for your team (regulated code, customer data in prompts, works council),
   turn prompt capture **off for the workspace** in Settings → Workspace *before* rolling out. The
   managed-settings download and the server both follow that policy; developers can additionally
   opt out per machine with `--no-prompts`. Tell your developers either way.
4. **Retention.** Settings → Data: pick automatic retention for usage data (prompt text always
   expires after 90 days).
5. **Budgets.** Limits → add an org monthly budget (and team ones). Developers see "% of budget" in
   `npx tokenfin@latest budget` and the optional statusline.

## 1. Managed settings for Claude Code (A)

Dashboard → **Connections** (`/dashboard/setup`) → **Roll out to your team** (owners/admins):

1. Optionally type a **team tag** (e.g. `platform`), then **Download managed-settings.json**.
   It's generated by `GET /api/v1/setup/managed-settings` and contains the OTel `env` block with
   your org's **ingest-only** key, `OTEL_RESOURCE_ATTRIBUTES=team.name=<tag>` (a
   `REPLACE_WITH_TEAM` placeholder if you left it empty), and `OTEL_LOG_USER_PROMPTS` only if the
   workspace allows prompt capture. The download is recorded in the audit log.
2. Deploy it to the path Claude Code reads (highest precedence; users can't override it):

   | OS | Path |
   |---|---|
   | macOS | `/Library/Application Support/ClaudeCode/managed-settings.json` |
   | Linux / WSL | `/etc/claude-code/managed-settings.json` |
   | Windows | `C:\Program Files\ClaudeCode\managed-settings.json` |

   Already shipping a managed-settings.json? Merge our `env` keys into it, or drop our file into the
   `managed-settings.d/` directory next to it (Claude Code merges the drop-ins).
3. Use the ready-made snippet on the page:
   - **Jamf Pro** (macOS): a root script that writes the file — scope a policy to developer Macs.
   - **Intune** (Windows): a PowerShell platform script. It writes UTF-8 **without BOM**
     (`[IO.File]::WriteAllText`) — a BOM makes the JSON unparseable.
   - **Ansible** (Linux/macOS): a playbook that copies the downloaded file to the right directory.
4. One file per team if you want per-team tags (download once per tag), or ship one file and tag
   teams some other way (Teams page budgets use membership, not the tag).

The key in that file is **ingest-only**: whoever reads it can send usage to your workspace but can't
read any analytics. File mode 0644 is fine for that reason. Rotate it by deactivating the
`setup-hub` key in API Keys and re-downloading.

Codex, Gemini and OpenCode have no managed-settings equivalent — developers who use them run the CLI.

## 2. Developers run the CLI (B)

Send this to the team:

> Run `npx tokenfin@latest setup` in a terminal. It opens a browser to sign in to TokenFin, creates
> keys for this machine, configures Claude Code / Codex / Gemini / OpenCode (whichever you have),
> and waits for your first event — then send one message in your agent.
> On a remote box / devcontainer: `npx tokenfin@latest login --device` first, approve the code in
> any browser, then `npx tokenfin@latest setup`.
> Prompt text is sent by default (90-day retention, admins can see it). To opt out:
> `npx tokenfin@latest setup --no-prompts`. Budget in your status bar: add `--statusline`.

Each machine gets **its own keys** (hostname + a stable device id): logging in on a laptop doesn't
break the desktop, and re-running login on the same machine rotates only that machine's keys and
re-points its agent configs automatically. Machines covered by managed settings still benefit from
the CLI for Codex/Gemini, `budget`, the statusline and MCP.

Members onboarded in bulk (`/dashboard/provision`) get a one-time reveal link instead; the reveal page shows
the exact `npx tokenfin@latest setup --key … --read-key …` command with a copy button.

## 3. Track the rollout

`/dashboard/setup` → **Rollout tracker** lists every member and pending invite with:

- **Status** — Active (event in the last 7 days), Quiet 7d+, Keys-no-events (logged in but nothing
  arrived — have them run `npx tokenfin@latest doctor`), Not set up, Invited.
- **Devices** — active per-device CLI keys (managed-settings users show events with 0 devices).
- **First event / Last seen / Source** (`claude_code`, `codex_cli`, …).

Chase "Keys, no events" first — that's almost always a stale shell, a revoked key (doctor says
`key revoked — run npx tokenfin@latest login`), or an old npx cache (tell them to use `@latest`).

## 4. Privacy defaults to communicate

- What's sent: model, token counts, cost, session/repo identifiers, the developer's email — and
  prompt text unless disabled (workspace or `--no-prompts`). Never model responses, files, or
  provider API keys. No proxy sits in the request path.
- Who sees it: workspace owners/admins see everything; members see their own usage (My usage).
- Retention: prompt text 90 days; usage per Settings → Data.
- Details for your DPO: `/privacy`.

## 5. Offboarding

1. Remove the member in **Teams**. All of their API keys (every device) are deactivated immediately;
   agents on their machines start getting `401` and send nothing further.
2. If they were on managed settings, their machine still has the org ingest key — remove the file
   via MDM when the device is returned. Events from a non-member email are not attributed to a
   person. If the laptop isn't coming back, rotate the org key (deactivate `setup-hub` in API Keys,
   re-download, redeploy).
3. Developers leaving a machine voluntarily: `npx tokenfin@latest remove` revokes that device's keys
   and removes all TokenFin config.
